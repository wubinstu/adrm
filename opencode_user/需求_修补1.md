## 一、Bug 修复

### 1. `-i` 交互式询问删除无反应

`-i` 参数输入后无反应，最好兼容 `/bin/rm` 的行为：

```
[ root: test ] # /bin/rm -i 1 9
/bin/rm: remove regular empty file '1'? y
/bin/rm: remove regular empty file '9'? n
```

### 2. 回收文件时有效时间参数绑定规则

最好严格控制时间参数与文件名的绑定关系。

**问题示例**：传入的文件只有三个，但时间却有四个，这时应该报错。

**解决方案**：强行规定为**向右亲和**。

- `adrm +1d 1 2 3` — `+1d` 同时作用于后面的 1、2、3
- `adrm 1 2 3 +1d` — 这是向左亲和，不做支持

**向右亲和规则**：
- `+Nd` 这种参数后面必须接文件名称
- 持续作用后面的所有文件直到遇到下一个类似于 `+Nd` 的参数
- `"-- +1d"` 转义符转义了 `+1d` 的特殊情况排除在外

**示例**：
```
adrm 1 +1d 2 +2d 3 +3d
```
- 文件 1：使用默认的时间期限
- 文件 2：使用 `+1d`
- 文件 3：使用 `+2d`
- `+3d`：报错（尾随时间参数没有后续文件）

同时因为命令行有错误应该提示并不做任何操作，包括文件 1、2、3 也不会被操作回收，**必须整个命令行是正确的才会执行**。

**Bug 现象**（当前错误行为，多一个时间参数也正常执行了）：
```
[ root: test ] # touch 1 2 3 4 5

[ root: test ] # adrm +1d 1 +2d 2 +3d 3 +4d

[ root: test ] # adrm --query
id  original_path               original_size  recycle_time         cleanup_time         status  
--  --------------------------  -------------  -------------------  -------------------  --------
3   /root/projects/adrm/test/3  0 B            2026-05-05 13:44:26  2026-05-08 13:44:26  recycled
2   /root/projects/adrm/test/2  0 B            2026-05-05 13:44:26  2026-05-07 13:44:26  recycled
1   /root/projects/adrm/test/1  0 B            2026-05-05 13:44:26  2026-05-06 13:44:26  recycled
```

### 3. `--reset-db` 逻辑缺陷

当前测试的行为是直接清空数据表，这显然不合理。

**期望行为**：
1. 执行 `adrm --reset-db` 时，先检查回收站是否为空（只要有一个文件仍然处于 `recycled` 就不能算空）
2. 如果为空则直接清表
3. 如果不为空，自动打印 `adrm --query --state recycled` 表项，并询问是否彻底清理回收站内所有文件然后再清表

---

### 4. `--deadline` 分钟和秒不能解析

```
[ root: test ] # adrm --deadline "2070/08/27 12:09" 5 

[ root: test ] # adrm --query
id  original_path               original_size  recycle_time         cleanup_time         status  
--  --------------------------  -------------  -------------------  -------------------  --------
```

### 5. `-I` 参数无效

`-I` 参数应该在文件数量超过 3 个时提示用户确认，但当前行为是直接静默删除，没有任何交互提示：

```
[ root: test ] # touch t1 t2 t3 t4
[ root: test ] # echo "n" | adrm -I t1 t2 t3 t4
（无任何提示，文件直接被全部回收）
```

---

### 6. `--restore` 和 `--clean` 默认行为错误

按照需求，`--restore` 默认恢复最近的一个文件，`--clean` 默认清理最近的一个文件。但当前行为是恢复/清理所有 `recycled` 状态的文件：

```
[ root: test ] # touch r1 r2 r3
[ root: test ] # adrm r1 r2 r3
[ root: test ] # adrm --restore
（r1, r2, r3 全部被恢复，应该只恢复 r3）

[ root: test ] # adrm r1 r2 r3
[ root: test ] # adrm --clean
（r1, r2, r3 全部被清理，应该只清理 r3）
```

---

### 7. `-R` 参数不被识别

help 信息中说明支持 `-R` 等同于 `-r`，但实际使用报错：

```
[ root: test ] # mkdir -p Rtest/sub && touch Rtest/sub/f
[ root: test ] # adrm -R Rtest
adrm: invalid option -- 'R'
（显示帮助信息，未执行任何操作）
```

---

### 8. `--recursive` 长选项不被识别

```
[ root: test ] # adrm --recursive Rtest
adrm: cannot remove '--recursive': No such file or directory
```

`--recursive` 被当作文件名处理了。

---

### 9. `-d` 参数无效

`-d` 应该移除空目录，但当前行为报错：

```
[ root: test ] # mkdir emptydir
[ root: test ] # adrm -d emptydir
adrm: cannot remove 'emptydir': Is a directory
```

---

### 10. 还原文件时未恢复特殊权限位

回收带有 suid/setgid/sticky 等特殊权限位的文件后还原，特殊权限位丢失（仅 suid 位丢失，sticky 位保留）：

```
[ root: test ] # touch suidfile && chmod u+s suidfile
[ root: test ] # ls -la suidfile
-rwSr--r-- 1 root root 0 ... suidfile

[ root: test ] # adrm suidfile
[ root: test ] # adrm --restore
[ root: test ] # ls -la suidfile
-rw-r--r-- 1 root root 0 ... suidfile
```

> suid 位丢失，数据库中记录了 `original_special_perm=4000`，但还原时未应用。

## 二、新增优化需求

### 1. 排序功能（--sort-asc / --sort-des）

为 `adrm --query-all` 和 `--query` 增加 `--sort-asc`/`--sort-des` 可选项，支持以下字段：

```
id / fname / fdate / fsize / rdate / cdate / state
```

**用法示例**：

```
adrm --query --sort-asc id          按 id 从小到大排序
adrm --query --sort-des fsize       按原始文件大小从大到小排序
```

**多字段排序**：如果出现多个 sort 选项，则按照先后出现的优先级进行：

```
adrm --query --sort-asc id --sort-des cdate
```

先按照 id 自增排序，再按照 cdate 自降排序。

**排序规则**：
- `state` 等特殊字段排序规则：直接按照字符串 `"recycled"/"restored"/"cleaned"/"exception"` 排序
- 日期字段：依次按照 "年月日时分秒" 数值大小排序（比如 2001 年任意时刻总是小于 2002 年任意时刻）

---

### 2. 彩色输出（--color）

为 `adrm --query-all` 和 `--query` 增加 `--color` 选项，使用 shell 颜色字符转义编码进行更人性化的展示。

**状态颜色**：

| 状态 | 颜色 |
|------|------|
| `exception` | 红色 |
| `cleaned` | 黄色 |
| `restored` | 绿色 |
| `recycled` | 蓝色 |

---

### 3. `--clear` 安全判定

为 `adrm --clear` 增加一个安全判定：
1. 先将过期的文件打印出来
2. 然后交互式提问是否要全部清理
3. 若没有文件过期则跳过安全判定

### 5. install.sh 安装脚本

当前目录下的 `./.github/workflows/release.yml` 以及 `./install.sh` 是后面新增的，用于提交 GitHub 自动编译和发布。

关于 install 脚本的修改：
1. 运行后要询问**二进制安装位置**（用户如果直接回车则默认为 `~/.local/bin`）
2. 然后第二次询问**家目录位置**（用户如果直接回车则默认为 `~/.adrm/`）
3. 最后询问**是否创建别名**（用户如果直接回车则默认为是）
4. 自动在 `.bashrc` 之类或者其他环境变量文件中添加：
   ```
   export alias rm="ADRM_HOME=用户指定的家路径 用户指定的安装路径/adrm"
   ```
