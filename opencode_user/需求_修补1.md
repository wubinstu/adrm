
根据本文件夹下的 "需求_初始.md" 版本进行手动测试, 绝大多数功能已经正常了!
但是仍有几个美中不足的地方:

1. adrm -i 交互式询问删除文件, 这个 -i 参数输入后无反应, 最好兼容 /bin/rm, 比如:
      [ root: test ] # /bin/rm -i 1 9
      /bin/rm: remove regular empty file '1'? y
      /bin/rm: remove regular empty file '9'? n

2. 回收文件时文件的有效时间参数设置, 最好严格控制一下, 比如在删除多个文件时, 这里传入的文件只有三个, 但是时间却是有四个, 这时应该报错, 建议将 时间参数和文件名参数严格绑定, 可以强行规定向左亲和或者向右亲和, adrm +1d 1 2 3 比如这就是向右亲和 (+1d同时作用 1 2 3), 而 adrm 1 2 3 +1d 就是向左亲和 (+1d同样同时作用 1 2 3), 这样像我下面的写法就显而易见的错误的 (因为多一个时间参数数量将文件全部夹在中间他看起来同时满足向左/向右亲和的写法), 那么就规定为必须向右亲和, 即 +1d 这种参数后面必须接文件名称, 并持续作用后面的所有文件知道遇到下一个类似于 +1d 这样的参数 (但 "-- +1d" 转义符转移了 +1d 文件的特殊情况排除在外), 比如 adrm 1 +1d 2 +2d 3 +3d, 那么文件 1 应该使用默认的时间期限, 文件 2 使用 +1d, 文件 3 使用 +2d, +3d 报错, 同时因为命令行有错误应该提示并不做任何操作, 包括文件 1,2,3 也不会被操作回收, 必须整个命令行是正确的才会执行
        [ root: test ] # touch 1 2 3 4 5

        [ root: test ] # adrm +1d 1 +2d 2 +3d 3 +4d

        [ root: test ] # adrm --query
        id  original_path               original_size  recycle_time         cleanup_time         status  
        --  --------------------------  -------------  -------------------  -------------------  --------
        3   /root/projects/adrm/test/3  0 B            2026-05-05 13:44:26  2026-05-08 13:44:26  recycled
        2   /root/projects/adrm/test/2  0 B            2026-05-05 13:44:26  2026-05-07 13:44:26  recycled
        1   /root/projects/adrm/test/1  0 B            2026-05-05 13:44:26  2026-05-06 13:44:26  recycled


3. adrm --reset-db, 有点逻辑缺陷, 当前测试的行为是直接清空数据表, 这显然不合理, 但回收站内不空, 多个文件仍然处于 recycled 状态时不能执行清表操作, 所以修改为这样会好点: 执行 adrm --reset-db 时, 先检查回收站是否为空 (只要有一个文件仍然处于 recycled 就不能算空), 如果为空则直接清表, 如果不为空, 自动打印 adrm --query --state recycled 表项, 并询问是否彻底清理回收站内所有文件然后再清表

4. --deadline 时间解析有问题: (分钟和秒不能解析)
        [ root: test ] # adrm --deadline "2070/08/27 12:09" 5 

        [ root: test ] # adrm --query
        id  original_path               original_size  recycle_time         cleanup_time         status  
        --  --------------------------  -------------  -------------------  -------------------  --------
        5   /root/projects/adrm/test/5  0 B            2026-05-05 13:47:47  2070-08-27 12:00:00  recycled

5. adrm -I 参数无效: -I 参数应该在文件数量超过 3 个时提示用户确认, 但当前行为是直接静默删除, 没有任何交互提示:
        [ root: test ] # touch t1 t2 t3 t4
        [ root: test ] # echo "n" | adrm -I t1 t2 t3 t4
        (无任何提示, 文件直接被全部回收)

6. adrm --restore 和 --clean 默认行为错误: 按照需求, --restore 默认恢复最近的一个文件, --clean 默认清理最近的一个文件, 但当前行为是恢复/清理所有 recycled 状态的文件:
        [ root: test ] # touch r1 r2 r3
        [ root: test ] # adrm r1 r2 r3
        [ root: test ] # adrm --restore
        (r1, r2, r3 全部被恢复, 应该只恢复 r3)
        [ root: test ] # adrm r1 r2 r3
        [ root: test ] # adrm --clean
        (r1, r2, r3 全部被清理, 应该只清理 r3)

7. adrm -R 参数不被识别: help 信息中说明支持 -R 等同于 -r, 但实际使用报错:
        [ root: test ] # mkdir -p Rtest/sub && touch Rtest/sub/f
        [ root: test ] # adrm -R Rtest
        adrm: invalid option -- 'R'
        (显示帮助信息, 未执行任何操作)

8. adrm --recursive 长选项不被识别:
        [ root: test ] # adrm --recursive Rtest
        adrm: cannot remove '--recursive': No such file or directory
        (--recursive 被当作文件名处理了)

9. adrm -d 参数无效: -d 应该移除空目录, 但当前行为报错:
        [ root: test ] # mkdir emptydir
        [ root: test ] # adrm -d emptydir
        adrm: cannot remove 'emptydir': Is a directory

10. 还原文件时未恢复特殊权限位: 回收带有 suid/setgid/sticky 等特殊权限位的文件后还原, 特殊权限位丢失 (仅 suid 位丢失, sticky 位保留):
        [ root: test ] # touch suidfile && chmod u+s suidfile
        [ root: test ] # ls -la suidfile
        -rwSr--r-- 1 root root 0 ... suidfile
        [ root: test ] # adrm suidfile
        [ root: test ] # adrm --restore
        [ root: test ] # ls -la suidfile
        -rw-r--r-- 1 root root 0 ... suidfile
        (suid 位丢失, 数据库中记录了 original_special_perm=4000, 但还原时未应用)
