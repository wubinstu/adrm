## 1. 总则

### 1.1 C++ 标准

本项目使用 **C++23** 标准。可以自由使用 C++23 及之前所有标准的特性。

### 1.2 格式化工具

项目根目录提供 `.clang-format` 文件。所有代码提交前必须经过 clang-format 格式化：

```bash
clang-format -i -style=file <filename>
```

如果 clang-format 的结果与本文档冲突，以本文档为准，并在 `.clang-format` 中补充配置。

### 1.3 核心原则

- **一致性高于个人偏好**：整个项目必须看起来像一个人写的。
- **显式优于隐式**：如果一个设计决策可能导致歧义，选择显式表达。
- **嵌入式友好**：本项目面向嵌入式协议解析场景，关注内存占用、确定性、无异常。

## 2. 文件组织

### 2.1 目录结构 (示例)

```
decoder/
├── buffer.hpp          # 环形缓冲区
├── buffer.cpp
├── locator.hpp         # 帧定位策略
├── locator.cpp
├── decoder.hpp         # 解码器主类
├── decoder.cpp
├── validator.hpp       # 校验器
├── validator.cpp
├── byte.hpp            # 字节序工具（纯头文件）
└── index.hpp           # 环形步进器（纯头文件）
```

### 2.2 文件命名

- 全小写，单词之间用下划线 `_` 分隔。
- 头文件后缀 `.hpp`，源文件后缀 `.cpp`。
- 一个 `.hpp` 对应一个同名 `.cpp`（纯模板/内联头文件除外）。

```
buffer.hpp / buffer.cpp        ✅
Buffer.hpp / Buffer.cpp        ❌
buffer.h  / buffer.cc          ❌
```

### 2.3 一个文件一个主要类型

每个头文件应该围绕一个核心类/结构体组织。辅助类型如果仅被该核心类型使用，可以放在同一文件中。

### 3.2 头文件保护

每个头文件使用双重保护。**宏名不得以双下划线 `__` 开头**（C++ 标准保留给实现），使用项目名作为前缀：

```cpp

#pragma once
#ifndef DECODERFW_BUFFER_HPP_
#define DECODERFW_BUFFER_HPP_

// ... 内容 ...

#endif
```

规则：
- 前缀：`DECODERFW_`
- 格式：`DECODERFW_<大写文件名去掉点>_HPP_`
- 文件末尾的 `#endif` 后不写注释

### 3.3 `#include` 顺序

分三组，组间空一行，组内按字母排序（clang-format 自动完成）：

```cpp
// 第一组：C++ 标准库（尖括号）
#include <cstdint>
#include <memory>
#include <vector>

// 第二组：项目内头文件（双引号）
#include "buffer.hpp"
#include "locator.hpp"
```

规则：
- 标准库用 `< >`，项目头文件用 `" "`。
- 不使用 `../` 相对路径，由 CMake 的 include 路径解决。
- 在 `.cpp` 文件中，第一个 `#include` 必须是对应的 `.hpp`（确保头文件自包含）。

```cpp
// buffer.cpp
#include "buffer.hpp"   // ← 永远第一个

#include <cstring>      // ← 标准库

// 无项目头文件依赖则不写
```

- 源文件中不声明新类型、新函数（只实现 `.hpp` 中声明的）。

## 5. 命名空间

### 5.1 何时使用

所有用户可见的类型、函数、常量必须位于命名空间中。**禁止向全局命名空间注入任何标识符。**

### 5.2 命名空间命名

全小写，不加下划线：

```cpp
namespace decoderfw { ... };   // ✅ 协议解析框架
namespace bytefw { ... };      // ✅ 字节工具
```

### 5.3 命名空间格式

```cpp
namespace decoderfw {


    class BytesRingBuffer {
        // ...
    };


}  // namespace decoderfw
```

规则：
- 开 `{` 后空一行。
- 闭 `}` 前空一行。
- 闭 `}` 后写注释 `// namespace xxx`。
- 闭 `}` 后**不加**分号 `;`。
- 命名空间内部所有内容缩进 4 空格（`.clang-format` 中 `NamespaceIndentation: All`）。

### 5.4 `std::` 前缀的写法

**永远写全 `std::`**，即使已经在 `using namespace std;` 的作用域中——本项目**禁止** `using namespace std;`。

```cpp
std::uint32_t        // ✅
std::unique_ptr      // ✅
std::move            // ✅
std::vector          // ✅

uint32_t             // ❌ 缺少 std::
using namespace std; // ❌ 禁止
```

唯一例外：在 `.cpp` 文件的函数实现中，如果某个标准库类型被极高频使用，可以在函数顶部写 `using` 别名：

```cpp
// 可以
auto func() -> void {
    using ByteVec = std::vector<std::uint8_t>;
    ByteVec a, b, c;
}

// 禁止
using namespace std;
```

### 5.5 命名空间路径何时写全

在**声明**中永远写全命名空间路径：

```cpp
namespace decoderfw {

    auto func() -> void;   // ✅ 已经在命名空间内部

}

// 在命名空间外部引用时写全路径
decoderfw::BytesRingBuffer buf;   // ✅
BytesRingBuffer buf;              // ❌ 如果不在 decoderfw 内部
```

在**定义**（`.cpp` 文件）中，使用命名空间包裹而非每次写全路径：

```cpp
// ✅ 正确
namespace decoderfw {

    auto BytesRingBuffer::push(...) -> std::uint32_t {
        // ...
    }

}  // namespace decoderfw

// ❌ 错误：不要每次写全路径
auto decoderfw::BytesRingBuffer::push(...) -> std::uint32_t {
    // ...
}
```

### 5.6 跨命名空间引用

从一个命名空间引用另一个命名空间的类型时，写全路径：

```cpp
namespace decoderfw {

    // bytefw 在另一个命名空间中，写全路径
    auto result = bytefw::reverseByteOrder(value);

    // 同一命名空间中不需要前缀
    auto buf = BytesRingBuffer{4096};

}  // namespace decoderfw
```

## 6. 标识符命名

### 6.1 总表

| 类别 | 风格 | 示例 |
|------|------|------|
| 类 / 结构体 / 枚举 | PascalCase | `BytesRingBuffer`, `InnerSection`, `LocateResult` |
| 成员变量 | `_m_` + snake_case | `_m_buffer`, `_m_capacity`, `_m_head_lists` |
| 函数 | camelCase | `sizeLoad`, `findHeadTails`, `splitSpace` |
| 参数 | snake_case（无前缀） | `capacity`, `headTails`, `maxPatternLen` |
| 局部变量 | snake_case 或 camelCase | `counts`, `current`, `patternIdx` |
| 命名空间 | 全小写 | `decoderfw`, `bytefw` |
| 模板类型参数 | 全大写 | `STDINT`, `DST`, `SRC` |
| 模板非类型参数 | camelCase | `bits`, `size` |
| 宏 / `constexpr` 常量 | UPPER_SNAKE_CASE | `CRC_ALGO_CRC32`, `HW_ATTRIBUTE_PACKED` |
| 枚举值 | snake_case | `success`, `waiting`, `rubbish` |
| 类型别名 | PascalCase | `Byte`, `HeadTailList` |
| 文件名 | snake_case | `buffer.hpp`, `locator.cpp` |

### 6.2 类和结构体命名（PascalCase）

每个单词首字母大写，无下划线，无后缀：

```cpp
class BytesRingBuffer { ... };
class CRC_Calculator { ... };          // 缩写词全大写后接下划线 + PascalCase
class FrameBoundaryStrategy { ... };

struct InnerSection { ... };
struct SplitSpace { ... };

enum class LocateResult { ... };
enum class ByteOrder { ... };
```

**不添加类型后缀**（如 `_ct`, `_st`, `_et`, `_t`）。现代 IDE 可以在鼠标悬停时显示类型信息，后缀是冗余的。

### 6.3 成员变量（`_m_` + snake_case）

所有成员变量以 `_m_` 开头，后接 snake_case：

```cpp
class BytesRingBuffer {
    std::unique_ptr<Byte[]>  _m_buffer   = nullptr;
    std::uint32_t            _m_capacity = 0;
    CircularStepper<std::uint32_t> _m_read;
    CircularStepper<std::uint32_t> _m_write;
};
```

### 6.4 函数命名（camelCase）

首字母小写，后续单词首字母大写：

```cpp
auto sizeLoad() const noexcept -> std::uint32_t;
auto findHeadTails(...) -> InnerSection;
auto splitSpace(std::uint32_t index) const noexcept -> SplitSpace;
auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;
```

### 6.5 参数命名（snake_case，无前缀）

```cpp
// ✅ 正确
auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;
auto splitSpace(std::uint32_t index) const noexcept -> SplitSpace;
auto locate(const BytesRingBuffer& buf, std::uint32_t& start, std::uint32_t& length) const -> LocateResult;

// ❌ 错误：不要在参数前加下划线前缀
auto push(const Byte _data[], std::uint32_t _length) noexcept -> std::uint32_t;
```

### 6.6 局部变量

snake_case 或 camelCase 均可，但在同一个函数内保持统一：

```cpp
auto counts = 0U;
auto current = this->_m_write;
auto pattern = headTails[0];
auto matchIdx = static_cast<std::uint32_t>(idx.getNow());
```

### 6.7 枚举值

snake_case，全小写：

```cpp
enum class LocateResult {
    success,
    waiting,
    rubbish,
    exception,
};

enum class ByteOrder {
    little_endian,
    big_endian,
    unknown_endian,
};
```

### 6.8 缩写词的处理

常见缩写词保持全大写，作为一个单词处理：

```cpp
class CRC_Calculator { ... };          // CRC 全大写
auto getID() const -> std::uint32_t;   // ID 全大写
auto parseUDP(...);                    // UDP 全大写
auto calculateCRC(...);                // CRC 全大写但不在开头时也是全大写
```

### 6.9 布尔变量和函数

布尔变量/返回 bool 的函数，名称应能自然地读作 yes/no 问题：

```cpp
auto isEmpty() const noexcept -> bool;     // "is empty?" → yes/no
auto isFull() const noexcept -> bool;      // "is full?" → yes/no
bool hasChecksum = (config.checksum != nullptr);  // "has checksum?"
bool _m_inner_length_little_endian = true;        // 成员也适用
```

## 7. 类型设计

### 7.1 `class` vs `struct`

| 用途 | 使用 |
|------|------|
| 纯数据聚合（无私有成员、无方法、无虚函数） | `struct` |
| 有封装逻辑（私有成员、方法、虚函数、不变量） | `class` |

```cpp
// struct：纯数据
struct InnerSection {
    std::int64_t  _m_start  = -1;
    std::uint64_t _m_length = 0;
};

// struct：纯数据 + 简单构造
struct SplitSpace {
    std::uint32_t half_r;
    std::uint32_t half_w;
};

// class：有封装、有不变量
class BytesRingBuffer final {
public:
    explicit BytesRingBuffer(std::uint32_t capacity = 4096) noexcept;
    auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;
private:
    std::unique_ptr<Byte[]> _m_buffer = nullptr;
    std::uint32_t           _m_capacity = 0;
};

// class：多态基类
class FrameBoundaryStrategy {
public:
    virtual ~FrameBoundaryStrategy() noexcept = default;
    virtual auto locate(...) const -> LocateResult = 0;
protected:
    HeadTailList _m_head_lists;
};

// class：具体策略（叶类标记 final）
class FrameBoundary_HeadAllLength final : public FrameBoundaryStrategy {
    // ...
};
```

### 7.2 类型别名

使用 `using`（禁止 `typedef`）：

```cpp
using Byte = std::uint8_t;
using HeadTailList = std::vector<std::vector<Byte>>;
```

### 7.3 固定宽度整数

永远使用 `<cstdint>` 中的固定宽度类型，禁止使用 `int`、`long`、`unsigned`：

```cpp
std::uint8_t,  std::uint16_t,  std::uint32_t,  std::uint64_t
std::int8_t,   std::int16_t,   std::int32_t,   std::int64_t
```

```cpp
// ✅ 正确
auto sizeLoad() const noexcept -> std::uint32_t;
for (std::uint32_t i = 0; i < length; ++i) { ... }

// ❌ 错误
auto sizeLoad() const noexcept -> unsigned int;
for (int i = 0; i < length; ++i) { ... }
```

唯一例外：`main()` 函数的返回值可以用 `int`。

### 7.4 `enum class`

永远使用 `enum class`（scoped enum），禁止裸 `enum`：

```cpp
// ✅ 正确
enum class LocateResult {
    success,
    waiting,
    rubbish,
    exception,
};

// ❌ 错误
enum LocateResult {
    Success,
    Waiting,
    ...
};
```

可以指定底层类型以控制大小：

```cpp
enum class ByteOrder : std::uint8_t {
    little_endian = 0,
    big_endian    = 1,
};
```

## 8. 关键字排序规则

当多个关键字同时出现时，遵循以下从左到右的顺序：

### 8.1 声明中的关键字顺序

```
[friend] [static | virtual] [inline] [explicit] [constexpr] 返回类型 函数名(参数) [const] [noexcept] [override | final] [-> 尾置返回类型]
```

实际示例：

```cpp
// 普通 const 成员函数
[[nodiscard]] auto sizeLoad() const noexcept -> std::uint32_t;

// 静态函数
static auto findHeadTails(const BytesRingBuffer& buff, const HeadTailList& headTails) -> InnerSection;

// 虚函数
virtual auto locate(const BytesRingBuffer& buf, std::uint32_t& start, std::uint32_t& length) const -> LocateResult = 0;

// override 函数
auto locate(const BytesRingBuffer& buf, std::uint32_t& start, std::uint32_t& length) const -> LocateResult override;

// constexpr 函数
constexpr inline auto platformByteOrder() noexcept -> ByteOrder { ... }

// 构造函数
explicit BytesRingBuffer(std::uint32_t capacity = 4096) noexcept;
```

### 8.2 变量声明中的关键字顺序

```
[static] [constexpr] [inline] [const] [volatile] 类型 变量名 = 初始值;
```

```cpp
// 全局常量
constexpr inline CRC_CONFIG<std::uint8_t> CRC_ALGO_CRC8 = {...};

// static 成员
static auto generateTable(...) noexcept -> void;

// const 局部变量
const auto& pattern = headTails[0];

// constexpr + inline + const
constexpr inline const ByteOrder_et platform_byte_order = platformByteOrder();
```

### 8.3 `const` 的位置：西 const（const 在类型左边）

```cpp
// ✅ 正确：const 在左边
const auto& pattern = headTails[0];
const BytesRingBuffer& buf = ...;
const std::uint8_t* data = ...;

// 也允许：东 const（const 在右边），在函数返回类型处更自然
auto peek(std::uint32_t index, Byte& out) const noexcept -> bool;
//                                           ^^^^^ const 修饰函数
```

本项目**不强制**西 const 或东 const。但在函数签名中，`const` 修饰成员函数永远放在参数列表后面：

```cpp
auto sizeLoad() const noexcept -> std::uint32_t;   // ✅
auto const sizeLoad() noexcept -> std::uint32_t;   // ❌
```

### 8.4 `constexpr` vs `const`

| 场景 | 使用 |
|------|------|
| 编译期常量 | `constexpr` |
| 运行期不可变 | `const` |
| 函数可以在编译期求值 | `constexpr` |
| 函数参数的不可变性 | `const` |

```cpp
// 编译期常量
constexpr inline CRC_CONFIG<std::uint8_t> CRC_ALGO_CRC8 = {...};

// 运行期不可变引用
const auto& pattern = headTails[0];

// constexpr 函数
constexpr inline auto platformByteOrder() noexcept -> ByteOrder { ... }
```

## 9. 函数声明与定义

### 9.1 尾置返回类型

**所有函数声明统一使用尾置返回类型 `auto f() -> ReturnType`**：

```cpp
// ✅ 正确
auto sizeLoad() const noexcept -> std::uint32_t;
auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;
auto isEmpty() const noexcept -> bool;

// ❌ 错误
std::uint32_t sizeLoad() const noexcept;
bool isEmpty() const noexcept;
```

理由：函数名始终在最前面，便于搜索和阅读。

### 9.2 函数声明的完整格式

```cpp
/// @brief 返回环形缓冲区有效数据个数
[[nodiscard]] auto sizeLoad() const noexcept -> std::uint32_t;
```

组成部分（按顺序）：
1. Doxygen 注释（`///`）
2. 属性（`[[nodiscard]]`, `[[maybe_unused]]` 等）
3. `static` 或 `virtual`（如有）
4. `inline` 或 `constexpr`（如有）
5. `auto`
6. 函数名
7. `(参数列表)`
8. `const`（如有）
9. `noexcept`（如有）
10. `-> 返回类型`
11. `override` 或 `final`（如有）
12. `= 0` / `= default` / `= delete`（如有）

### 9.3 `noexcept`

所有**不抛异常**的函数标记 `noexcept`：

```cpp
auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;
auto clear() noexcept -> void;
~BytesRingBuffer() noexcept = default;
```

只有当函数**确实可能抛异常**时才省略 `noexcept`：

```cpp
// verify() 可能调用用户传入的 std::function，不标记 noexcept
[[nodiscard]] bool verify(const ChecksumFrame& frame) const noexcept = delete;  // 设计上不抛异常时仍标记
```

### 9.4 `[[nodiscard]]`

所有返回值不应被忽略的函数标记 `[[nodiscard]]`：

```cpp
[[nodiscard]] auto sizeLoad() const noexcept -> std::uint32_t;    // 必须使用返回值
[[nodiscard]] auto isEmpty() const noexcept -> bool;              // 必须使用返回值
```

### 10.2 放在头文件 `.hpp` 中的情况

以下情况函数体放在头文件中：

1. **模板函数**（必须在头文件中定义）
2. **`inline` 函数**（编译器需要在调用点看到定义）
3. **`constexpr` 函数**（需要在编译期可用）
4. **单行 getter/setter**（可以内联在类定义内）

```cpp
    // ...
}

// 单行 getter：可以内联在类中
[[nodiscard]] auto getMin() const noexcept -> STDINT { return this->_m_index_min; }
```

```
函数是模板吗？
├── 是 → 放在头文件中
└── 否 → 函数是 constexpr 吗？
         ├── 是 → 放在头文件中
         └── 否 → 函数体 <= 1 行且性能关键吗？
                  ├── 是 → 放在头文件中，标记 inline
```

## 12. `this->` 的使用

**所有成员变量和成员函数的访问一律使用 `this->`**。

```cpp
// ✅ 正确
auto BytesRingBuffer::push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t {
    if (!data || !length)
        return 0;

    auto counts = 0U;
    auto write  = this->_m_write;           // ✅ this-> 访问成员
    for (std::uint32_t i = 0; i < length; i++) {
        if (this->isFull())                 // ✅ this-> 调用成员函数
            break;
        this->_m_buffer[write++] = data[i]; // ✅ this-> 访问成员
        counts++;
    }
    if (counts)
        this->_m_write = write;             // ✅ this-> 访问成员
    return counts;
}

// ❌ 错误：省略 this->
auto counts = 0U;
auto write  = _m_write;                     // ❌ 缺少 this->
if (isFull())                               // ❌ 缺少 this->
    break;
_m_buffer[write++] = data[i];               // ❌ 缺少 this->
```

例外：在构造函数的初始化列表中可以省略 `this->`（因为初始化列表的语义就是初始化成员）：

```cpp
BytesRingBuffer::BytesRingBuffer(std::uint32_t capacity) noexcept :
    _m_buffer{std::make_unique<Byte[]>(capacity)}, _m_capacity{capacity} {
    //                                        ↑ 初始化列表中不需要 this->
}
```

## 13. `auto` 的使用

### 13.1 使用 `auto` 的情况

1. **初始化表达式能明确推导类型时**：

```cpp
auto counts = 0U;                    // unsigned int
auto write  = this->_m_write;        // CircularStepper<std::uint32_t>
auto sect   = this->_m_ac_head.search(buff);  // InnerSection
auto it     = tree[current].children.find(byte);  // map::const_iterator
```

2. **范围 for 循环**：

```cpp
for (const auto& [byte, child] : tree[0].children) { ... }
for (const auto& pattern : headTails) { ... }
for (auto& byte : buffer) { ... }
```

3. **函数返回类型（尾置返回类型语法要求）**：

```cpp
auto sizeLoad() const noexcept -> std::uint32_t;
```

4. **模板代码中类型依赖参数时**：

```cpp
auto result = static_cast<STDINT>(value);
```

### 13.2 不使用 `auto` 的情况

1. **需要明确控制类型时**：

```cpp
std::uint32_t counts = 0;             // 明确指定位宽
std::int64_t  matchIdx = -1;          // 明确指定有符号
```

2. **初始化表达式不足以推导出正确类型时**：

```cpp
auto value = 0;                       // int，但实际想要 std::uint32_t
// 应写为：
std::uint32_t value = 0;
```

3. **`auto` 会推导出引用而你需要值时**：

```cpp
auto copy = original;                 // 值拷贝（OK 如果需要拷贝）
const auto& ref = original;           // 引用（避免拷贝）
```

### 13.3 `auto` 与引用的组合

```cpp
auto        val  = expr;              // 值拷贝
auto&       ref  = expr;              // 可变引用
const auto& cref = expr;              // const 引用（推荐用于只读）
auto&&      uref = expr;              // 转发引用（仅在泛型代码中使用）
```

## 17. 空格与对齐

### 17.1 括号前的空格

| 位置 | 加空格？ | 示例 |
|------|---------|------|
| 控制语句关键字后 | **加** | `if (cond)`, `for (...)`, `while (...)`, `switch (...)` |
| 函数调用 / 声明 | **不加** | `push(data, length)`, `sizeLoad()` |
| 模板参数 | **不加** | `std::vector<Byte>`, `CircularStepper<std::uint32_t>` |
| 宏调用 | **加**（与宏定义保持一致） | `HW_ATTRIBUTE_PACKED` |

```cpp
// ✅ 正确
if (condition) { ... }
for (std::uint32_t i = 0; i < length; ++i) { ... }
while (!empty) { ... }
auto val = sizeLoad();
auto n = push(data, length);
auto ptr = std::make_unique<Byte[]>(capacity);

// ❌ 错误
if(condition) { ... }              // 控制语句后缺少空格
auto val = sizeLoad ();            // 函数调用前多了空格
auto n = push (data, length);      // 函数调用前多了空格
```

### 17.2 操作符周围

```cpp
// 赋值和二元操作符两边加空格
auto a = b + c;
this->_m_write = write;
if (this != &other) { ... }

// 一元操作符不加空格
if (!data) return 0;
auto val = *ptr;
auto ref = &var;
++i;
--i;
```

### 17.3 逗号和冒号后加空格

```cpp
void func(std::uint32_t a, std::uint32_t b, std::uint32_t c);
for (std::uint32_t i = 0; i < n; ++i) { ... }
```

### 17.4 初始化列表的大括号前加空格

```cpp
std::vector<Node> tree {};
std::make_unique<Byte[]>(capacity)
BytesRingBuffer(std::uint32_t capacity) noexcept :
    _m_buffer{std::make_unique<Byte[]>(capacity)}, _m_capacity{capacity} {
}
```

### 17.5 花括号内的空格

```cpp
// 空花括号不加空格
Node{}                        // ✅
Node{ }                       // ❌
std::vector<Node> tree {};    // ✅
std::vector<Node> tree { };   // ❌

// 非空花括号不加额外空格（由 clang-format 处理）
auto sect = InnerSection{-1, 3};
```

### 17.6 对齐

相邻声明的赋值号 `=`、变量名、类型名尽量对齐（clang-format 的 `AlignConsecutive*` 会自动完成）：

```cpp
// 成员声明对齐
std::unique_ptr<Byte[]>                    _m_buffer   = nullptr;
std::uint32_t                              _m_capacity = 0;
CircularStepper<std::uint32_t>             _m_read;
CircularStepper<std::uint32_t>             _m_write;

// 赋值对齐
this->_m_buffer    = std::move(other._m_buffer);
this->_m_capacity  = other._m_capacity;
this->_m_read      = std::move(other._m_read);
this->_m_write     = std::move(other._m_write);

other._m_buffer    = nullptr;
other._m_capacity  = 0;
```

## 18. 注释风格

### 18.1 三种注释的使用场景

| 场景 | 注释风格 | 示例 |
|------|---------|------|
| 函数/类型文档 | `///` Doxygen | `/// @brief ...` |
| 行内说明 | `//` 单行 | `auto val = 0;  // 说明` |
| 文件头 | `/** */` 块注释 | 文件头许可证 |
| 禁用代码段 | `//` | `// auto old = ...;` |

### 18.2 Doxygen 文档注释 `///`

用于所有**公开 API** 的函数、类、结构体、枚举：

```cpp
/// @brief 推入字节流, 并返回实际成功推入的数量
/// @param data 源数据指针
/// @param length 要推入的字节数
/// @return 实际推入的字节数
auto push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t;

/// @brief 查看指定位置的字节
/// @param index 缓冲区绝对下标
/// @param out 输出数据
/// @return 输出的数据是否是有效的
auto peek(std::uint32_t index, Byte& out) const noexcept -> bool;

/// @brief 返回环形缓冲区有效数据个数
[[nodiscard]] auto sizeLoad() const noexcept -> std::uint32_t;
```

### 18.3 行内注释 `//`

用于代码逻辑说明：

```cpp
auto maxPatternLen = 0;  // 帧头/帧尾 最大长度

// 先恢复辅助结构体状态, 用于重新单独匹配
for (std::uint32_t i = 0; i < headTails.size(); ++i)
    cache[i] = init;

// 如果走一圈全军覆没, 则直接下一个轮次
bool allFailed = true;
```

规则：
- `//` 后接一个空格。
- 行尾注释前至少两个空格：`auto val = 0;  // 注释`。
- 注释用中文或英文均可，但**同一文件内保持统一**。
- **注释解释"为什么"，不解释"做什么"**——代码本身应该说明"做什么"。

### 18.4 块注释 `/** */`

仅用于文件头。不要在代码中间使用 `/* */` 块注释（无法嵌套，容易出问题）。

### 18.5 禁止的注释行为

```cpp
// ❌ 不要注释掉的大段代码（用 git 管理历史）
// auto old_code = 0;
// if (old_code) {
//     ...
// }

// ❌ 不要写无意义的注释
auto i = 0;  // 将 i 设为 0

// ❌ 不要用注释分隔逻辑块（用空行即可）
// ========== 下面是push函数 ==========
```

```cpp
      public:
        explicit CircularStepper(STDINT min = 0, STDINT max = 100, STDINT step = 1) noexcept;

        std::atomic<STDINT> _m_index_max = 100;

namespace decoderfw {

    template <typename STDINT>
    CircularStepper<STDINT>::CircularStepper(STDINT min, STDINT max, STDINT step) noexcept {
```


## 23. 现代 C++ 特性清单

### 23.1 必须使用的特性

| 特性 | 用途 |
|------|------|
| `enum class` | 强类型枚举，替代裸 `enum` |
| `std::unique_ptr` | 所有权管理，替代裸 `new`/`delete` |
| `std::move` | 右值转换 |
| `= default` / `= delete` | 显式控制特殊成员函数 |
| `override` | 虚函数重写标记 |
| `final` | 禁止继承/重写 |
| `[[nodiscard]]` | 返回值不可忽略 |
| `noexcept` | 不抛异常保证 |
| `explicit` | 禁止隐式转换 |
| `constexpr` | 编译期求值 |
| 尾置返回类型 | 统一函数声明风格 |
| `using` | 类型别名（替代 `typedef`） |
| 初始化列表 `{}` | 统一初始化 |
| `auto` | 类型推导（参见第 13 章） |
| 结构化绑定 | `const auto& [key, val] : map` |

### 23.2 禁止使用的特性

| 特性 | 原因 |
|------|------|
| `using namespace std;` | 命名空间污染 |
| `typedef` | 使用 `using` 替代 |
| 裸 `enum` | 使用 `enum class` 替代 |
| `new` / `delete` | 使用 `std::make_unique` / `std::make_shared` |
| C 风格转换 | 使用 `static_cast` 等 |
| `NULL` | 使用 `nullptr` |
| `goto` | 使用结构化控制流 |
| `volatile`（非硬件寄存器场景） | 使用 `std::atomic` |
| 异常 | 本项目面向嵌入式，禁用异常 |

### 23.3 `virtual` + `override` / `final`

```cpp
// 基类：声明 virtual
class Base {
public:
    virtual auto locate(...) const -> LocateResult = 0;
    virtual ~Base() noexcept = default;
};

// 派生类：不加 virtual，加 override
class Derived final : public Base {
public:
    auto locate(...) const -> LocateResult override;     // ✅ override
    // virtual auto locate(...) const -> LocateResult override;  // ❌ 派生类不加 virtual
};
```

规则：
- 基类虚函数写 `virtual`。
- 派生类重写时**不写 `virtual`**，只写 `override`。
- 叶类标记 `final`。

### 24.1 列限制

```cpp
#include "ring_buffer.hpp"

namespace decoderfw {


    RingBuffer::RingBuffer(std::uint32_t capacity) noexcept :
        _m_buffer{std::make_unique<Byte[]>(capacity)}, _m_capacity{capacity} {
    }

    RingBuffer::RingBuffer(RingBuffer && other) noexcept {
        this->_m_buffer   = std::move(other._m_buffer);
        this->_m_capacity = other._m_capacity;
        this->_m_read     = other._m_read;
        this->_m_write    = other._m_write;

        other._m_buffer   = nullptr;
        other._m_capacity = 0;
        other._m_read     = 0;
        other._m_write    = 0;
    }

    RingBuffer & RingBuffer::operator=(RingBuffer && other) noexcept {
        if (this != &other) {
            this->_m_buffer   = std::move(other._m_buffer);
            this->_m_capacity = other._m_capacity;
            this->_m_read     = other._m_read;
            this->_m_write    = other._m_write;

            other._m_buffer   = nullptr;
            other._m_capacity = 0;
            other._m_read     = 0;
            other._m_write    = 0;
        }
        return *this;
    }

    auto RingBuffer::push(const Byte data[], std::uint32_t length) noexcept -> std::uint32_t {
        if (!data || !length)
            return 0;

        auto counts = 0U;
        for (std::uint32_t i = 0; i < length; ++i) {
            if (this->isFull())
                break;
            this->_m_buffer[this->_m_write] = data[i];
            this->_m_write = (this->_m_write + 1) % this->_m_capacity;
            counts++;
        }
        return counts;
    }

    auto RingBuffer::peek(std::uint32_t index, Byte & out) const noexcept -> bool {
        if (index >= this->_m_capacity)
            return false;

        // 检查 index 是否在有效数据范围内 [read, write)
        auto load = this->sizeLoad();
        if (load == 0)
            return false;

        // 简化的范围检查
        auto readIdx  = this->_m_read;
        auto writeIdx = this->_m_write;

        if (writeIdx > readIdx) {
            if (index >= readIdx && index < writeIdx) {
                out = this->_m_buffer[index];
                return true;
            }
        } else if (writeIdx < readIdx) {
            if (index >= readIdx || index < writeIdx) {
                out = this->_m_buffer[index];
                return true;
            }
        }

        return false;
    }

    auto RingBuffer::consume(std::uint32_t length) noexcept -> std::uint32_t {
        auto load = this->sizeLoad();
        if (length > load)
            length = load;

        this->_m_read = (this->_m_read + length) % this->_m_capacity;
        return length;
    }

    [[nodiscard]] auto RingBuffer::sizeLoad() const noexcept -> std::uint32_t {
        if (this->_m_write >= this->_m_read)
            return this->_m_write - this->_m_read;
        else
            return this->_m_write + (this->_m_capacity - this->_m_read);
    }

    [[nodiscard]] auto RingBuffer::isEmpty() const noexcept -> bool {
        return this->_m_read == this->_m_write;
    }

    [[nodiscard]] auto RingBuffer::isFull() const noexcept -> bool {
        return this->_m_read == (this->_m_write + 1) % this->_m_capacity;
    }

    auto RingBuffer::clear() noexcept -> void {
        this->_m_read  = 0;
        this->_m_write = 0;
        if (this->_m_buffer)
            std::memset(this->_m_buffer.get(), 0, this->_m_capacity);
    }

    auto RingBuffer::operator[](std::uint32_t index) const -> Byte {
        return this->_m_buffer[index];
    }


}  // namespace decoderfw
```

```cpp
    template <typename STDINT>
    CircularStepper<STDINT>::CircularStepper(STDINT min, STDINT max, STDINT step) noexcept {
        if ((min < max) && (step < (max - min))) {
            this->_m_index_min  = min;
            this->_m_index_max  = max;
            this->_m_index_step = step;
        }
        this->_m_index_now = this->_m_index_min.load();

        this->_m_index_min.store(other._m_index_min.load());
        this->_m_index_max.store(other._m_index_max.load());
        this->_m_index_step.store(other._m_index_step.load());
        this->_m_index_now.store(other._m_index_now.load());
    }

    CircularStepper<STDINT>::CircularStepper(CircularStepper && other) noexcept {
        this->_m_index_min.store(other._m_index_min.exchange(0));
        this->_m_index_max.store(other._m_index_max.exchange(100));
        this->_m_index_step.store(other._m_index_step.exchange(1));
        this->_m_index_now.store(other._m_index_now.exchange(0));

            this->_m_index_max.store(other._m_index_max.load());

            this->_m_index_now.store(other._m_index_now.load());
        }

        }
```
