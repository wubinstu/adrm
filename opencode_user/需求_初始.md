# adrm — 初始需求文档

## 概述

adrm 用于替换 Linux/Unix 原生自带的 `/bin/rm`。

---

## 0. 核心功能

将 "删除" 这个语义替换为 "回收站"，所有的删除都只是移动到回收站。

---

## 1. 命令行参数兼容性

命令行参数需要兼容 `/bin/rm --help` 中的内容（至少兼容 `-fiIrdv/--`），支持一次性传入多个文件和文件夹。

---

## 2. 目录结构与配置

- **默认主目录**: `~/.adrm`（可通过 `ADRM_HOME=/path/to/adrm/` 这种 shell 环境变量重定向）
- **配置文件**: `~/.adrm/config`（如果设置了 `ADRM_HOME`，那么就是 `$ADRM_HOME/config`）
- **忽略规则文件**: `~/.adrm/ignore`（和 gitignore 同语法规则）
  - 当某文件满足忽略规则时则只提示而不回收（除非有 `-f` 参数，则可以无视 ignore 规则）
  - 可自定义 ignore 文件路径（在配置文件中修改）
- **数据库文件**: `~/.adrm/files.db`（可自定义数据库文件路径，在配置文件中修改）
- **回收站路径**: `~/.adrm/trash/`（可自定义回收站路径，在配置文件中修改）
- **`adrm --default`**: 可以生成一个默认的配置文件，包含了完整的默认配置和注释说明

---

## 3. 权限鉴别

有完善的权限鉴别，adrm 的运行者的权限不足以回收（回收的本质其实是移动文件/目录的位置）某文件时停止操作并提示。

---

## 4. 内部数据库

内部静态链接嵌入如 SQLite 之类的轻量级数据库。

---

## 5. 数据表结构

每个回收的文件插入数据表中，数据表包含以下字段：

| 字段 | 说明 |
|------|------|
| 主键序号 | 自增整数 |
| 原始文件名(+路径) | 完整的绝对路径 |
| 原始文件修改日期 | |
| 原始文件大小 | human readable |
| 原始文件常规权限位 | |
| 原始文件特殊权限位 | |
| 原始文件属主 | |
| 原始文件属组 | |
| 回收后重新编码的文件名(+路径) | 完整的绝对路径 |
| 回收日期 | 年月日时分秒 |
| 彻底清理日期 | 年月日时分秒 |
| 文件状态 | 已回收/已还原/已清理/异常 |

---

## 6. 数据表详细说明

- **主键**: 数据库中的主键就用自增整数。
- **路径存储**: 原始文件名(+路径)/回收后重新编码的文件名(+路径) 这种直接存储完整的绝对路径。
- **文件名重新编码**: 这是为了防止回收目录中出现同名文件/目录。当用户回收一个文件时，需要对文件名称进行重新编码，可以用 UUID，也可以在文件名称开头和结尾加上日期/哈希之类的尾巴。向数据库中保存记录时同时保存原始文件的路径名称和重新编码后的路径名称。
- **文件状态**:
  - 已回收/已还原/已清理 — 很好理解
  - 异常 — 当 adrm 对文件做移动、重命名、恢复各种属性等各种必要操作时如果出现了未知错误，则将其标记为异常并停止操作并打印日志通知用户

---

## 7. 数据表项与目录标记

数据表中的每个表项都是传入命令行的文件/目录。数据库表项只增长，当文件被还原/彻底清理时该表项则已完成，只有一个记录的作用，即用户查看操作历史的作用，adrm 不再跟踪和管理该文件。

只有状态为回收中的文件才是 adrm 跟踪和管理的文件。如果传入的是个目录，插入数据库中时应该在文件夹名称后显示的加入一个 `/`，比如 `work/`，这样用户根据末尾的 `/` 符号可以判断是文件/目录。

---

## 8. 回收文件/目录

### 基本用法

```
adrm file1              回收 file1
adrm -r path2/          整体回收目录2（整体移动目录到回收站）
adrm -f file1           忽略读写保护直接回收文件
adrm -i file1 file2     交互式提示回收文件
adrm -rf file1 path2/   直接回收并在数据库中新增两个表项
adrm -- -file1          回收一个文件名称为 "-file1" 的文件
```

### 相对时间（有效期）

```
adrm file1 +6d              有效时间 6 天
adrm file1 +20h             有效时间 20 小时
adrm file1 +1s              有效时间 1 秒
adrm file1 +5m              有效时间 5 分钟
```

> 没有月，没有年，表达更长时间单位那就比如 `+730d`（约2年），这种超长时间单位推荐使用下方的 `--deadline` 参数。

### 多文件与时间绑定

```
adrm file1 file2 path3/ +3d             文件1,2和目录3都为3天有效
adrm file1 +3d file2 +4d path3/ +5d     文件1有效3天, 文件2有效4天, 目录3有效5天
adrm file1 +3d4h5m                      文件有效3天4小时5分钟
```

### 特殊文件名转义

```
adrm -- +this_is_a_file    某些文件确实以 + 开头，则必须用 -- 转义
```

### 绝对时间（--deadline）

支持的日期分隔符: `/` `_` `-`，支持的时间格式: `HH:MM` `HH:MM:SS`

```
adrm file1 --deadline "2027/01/01"          有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027/1/01"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027/01/1"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027/1/1"            有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027/1/1 3:45"       有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027/1/1 03:45"      有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027/1/1 03:45:01"   有效直到 2027年1月1日 03:45:01
adrm file1 --deadline "2027_01_01"          有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027_1_01"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027_01_1"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027_1_1"            有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027_1_1 3:45"       有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027_1_1 03:45"      有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027_1_1 03:45:01"   有效直到 2027年1月1日 03:45:01
adrm file1 --deadline "2027-01-01"          有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027-1-01"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027-01-1"           有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027-1-1"            有效直到 2027年1月1日 00:00:00
adrm file1 --deadline "2027-1-1 3:45"       有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027-1-1 03:45"      有效直到 2027年1月1日 03:45:00
adrm file1 --deadline "2027-1-1 03:45:01"   有效直到 2027年1月1日 03:45:01
```

### 默认有效期

若不指定彻底清理的日期，则默认 30 天，可在配置文件中修改。

### 过期清理机制

本程序没有守护进程，无需实时检测文件的有效日期。当手动 `adrm --clear` 单次运行时检查并清理过期文件即可。换句话说就是即使被回收的文件过期了，只要不再次运行 `adrm --clear` 也不会被删除。

---

## 9. 查看数据库

```
adrm --query-all        打印完整数据库
adrm --query            默认打印最近 10 条记录（按照主键自增排序）（打印简略数据库，将上述数据表中关键的信息进行显示，相对不重要的不显示，具体要显示的项目可以在配置文件中修改，配置文件中可以自由定义需要打印的列以及先后顺序）
adrm --query [可选的过滤条件]
adrm --query --help     只显示 --query 的示例用法/帮助信息
```

---

## 10. 还原文件

文件还原指的是将重新编码命名后的文件/目录，还原到原始原始路径并保持属主/属组/各种权限位/日期不变，同时更新数据库文件状态为已还原。

```
adrm --restore-all          还原所有文件
adrm --restore              默认恢复最近的一个文件/目录（如果最近的一个数据库记录的状态不是回收中，比如已还原/已清理，则只提示不做任何操作）
adrm --restore [可选的过滤条件]
adrm --restore --help       只显示 --restore 的示例用法/帮助信息
```

---

## 11. 彻底清理文件

彻底清理文件指的是根据数据库中 "回收后重新编码的文件名(+路径)" 找到实际的文件/目录，然后将其真正删除，并更新数据库文件状态为已清理。

```
adrm --clean-all            清空回收站
adrm --clean                默认彻底清理最近一个文件/目录（如果最近的一个数据库记录的状态不是回收中，比如已还原/已清理，则只提示不做任何操作）
adrm --clean [可选的过滤条件]
adrm --clean --help         只显示 --clean 的示例用法/帮助信息
```

---

## 可选的过滤条件（适用于 --query / --restore / --clean）

### 按主键过滤

```
--id 10       选中数据库中主键为 10 的表项
--id +10      选中数据库中主键大于等于 10 的表项
--id -10      选中数据库中主键小于等于 10 的表项
```

> 数字必须紧贴着 `--id` 命令行参数，数字单独出现无效。

### 按记录数量过滤

```
--items 10    选中数据库中距离最新记录的 10 条记录
```

> 数字必须紧贴着 `--items` 命令行参数，数字单独出现无效。

### 按文件名过滤

```
--fname "happy"    选中数据库中原始文件名(+路径)中包含 happy 字符串的表项，忽略大小写
```

> 名字字符串必须紧贴着 `--fname` 命令行参数，名字字符串单独出现无效。

### 按原始文件修改日期过滤（--fdate）

```
--fdate 3d4h5m              选中原始文件修改日期距离当前时间恰好 3天4小时5分钟 的表项，忽略秒差异
--fdate +3d5m7s             选中原始文件修改日期距离当前时间 大于等于3天5分钟7秒 的表项
--fdate -121d               选中原始文件修改日期距离当前时间 小于等于121天 的表项
--fdate "2027-1-1 03:45:01" 选中原始文件修改日期恰好为 "2027年1月1日 03:45:01" 的表项
--fdate "+2027/1/1 3:45"    选中原始文件修改日期大于等于 "2027年1月1日 03:45" 的表项
--fdate "-2027_01_01"       选中原始文件修改日期小于等于 "2027年1月1日" 的表项
```

> 参数值必须紧贴着 `--fdate` 命令行参数，单独出现无效。

### 按原始文件大小过滤（--fsize）

```
--fsize 10t20g30m40k50b     选中原始文件大小恰好为 "10TB+20GB+30MB+40KB+50Bytes" 的表项
--fsize +30m50b             选中原始文件大小大于等于 "30MB+50Bytes" 的表项
--fsize -1g                 选中原始文件大小小于等于 "1GB" 的表项
```

> 参数值必须紧贴着 `--fsize` 命令行参数，单独出现无效。

### 按回收日期过滤

```
--rdate    过滤回收日期，后面接的具体时间或时间运算规则参数和 --fdate 一致
```

### 按清理日期过滤

```
--cdate    过滤彻底清理日期，后面接的具体时间或时间运算规则参数和 --fdate 一致
```

### 按文件状态过滤

```
--state recycled      选中文件状态为 已回收 的表项
--state restored      选中文件状态为 已恢复 的表项
--state cleaned       选中文件状态为 已清理 的表项
--state exception     选中文件状态为 异常 的表项
```

### 组合过滤

可选的过滤条件可以组合使用，表示逻辑"与/且/AND"。

```
--id +10 --fsize -1g --state cleaned
```

表示选中数据库中主键大于等于10，且原始文件大小在 1GB 及以内，且文件状态为已清理的表项。

---

## 12. 重置数据库

若执行 `adrm --reset-db`，则清空数据库重新开始记录。如果数据库中仍然存在状态为"回收中"的文件/目录，则此操作只提醒，不进行实际操作。

---

## 13. 数据库加锁保护

最后注意数据库要做加锁保护，如果数据库原生支持异步批量读写保护，则忽略。
